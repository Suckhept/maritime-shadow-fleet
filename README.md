# Maritime Shadow Fleet & Energy Provenance Map

A GRC-20 dataset + a Next.js explorer for the Geo *World affairs* bounty. It traces how sanctioned
oil moves — from a vessel, to a **related company**, to a destination — using sanctions data
from official listings (OFAC / UK). Sanctions and corporate-link assertions are primary-source-backed;
the reported voyage and port coordinates carry separately-labelled secondary provenance. Nothing is
invented: identifiers, owners and dates come from official listings, and every relation predicate is
matched to the exact wording of a document that proves it.

## How sanction status is modelled (important)

A designation's `currentStatus` is **three-valued**: `active | removed | current-unverified`. Every
OFAC SDN record was **re-verified against the live OFAC Sanctions List Search on 2026-06-15** (SDN List
version 2026-06-11): vessels by exact-IMO lookup, companies by name/UID. Result: **all OFAC records
confirmed currently listed → `active`** (`statusVerifiedAt = 2026-06-15`, each with its OFAC detail page
`Details.aspx?id=<UID>` as `statusSource`), **except** Yasa Golden Bosphorus and Ice Pearl Navigation
Corp, which return zero results → `removed` (delisted 2024-04-26). **Lunar Tide** is `active` (dated UK
notice, 2026-02-10). **Winky International Limited** is `active` (OFAC UID **56723**, Venezuela
programme). No record currently carries `current-unverified`. Per-record OFAC UIDs are logged in
`data/SOURCES.md` and `data/ofac-verification.json`.

**One hull, two listings.** IMO **9277735** is **dual-listed**: the **UK** Russia regime lists it as
*Lunar Tide* (current owner-operators West Maritime, UID RUS2841, 2026-02-10), while **OFAC** lists the
same hull as *ROSALIND (a.k.a. Lunar Tide)*, Guinea flag, under the **Venezuela** programme (2025-12-31).
The Treasury press release **sb0348** names **Winky International Limited** as ROSALIND's *registered
owner* and identifies the vessel as *blocked property in which Winky has an interest* — so two dated
relations to Winky are recorded (`registeredOwner` + `interestHolder`). The OFAC registered-owner
(Winky, 2025-12-31) and the UK owner-operator (West Maritime, 2026-02-10) are **not reconciled**: this
is flagged on the relations as a *source discrepancy / possible role change* (`roleCurrency = unverified`),
deliberately **not** collapsed into a single "current owner" without registry (Equasis/GISIS) data. Flag
is **Guinea** per the OFAC entry (`flagSourceUrl` → OFAC); the UK notice had struck an erroneous value.

## Provenance: two URLs per relation

Each relation stores both the **listing action** that lists the two entities together
(`listingSourceUrl`) and the **document that proves the predicate** (`predicateEvidenceUrl`), plus an
`evidenceQuote` and `evidenceDate`. Example: Sovcomflot's `interestHolder` listing is OFAC Recent
Actions 20240223, but the "property in which Sovcomflot has an interest" wording lives in Treasury
press release **jy2121** — so the edge opens jy2121. The trace table and the in-graph **edge-click
panel** both surface predicate + quote + both URLs + confidence.

## Notable corrections

- **Yasa Golden Bosphorus + Ice Pearl**: OFAC **delisted** both on **26 Apr 2024** (Recent Actions
  20240426). They are kept as a historical case with `currentStatus = removed`, `dateRemoved =
  2024-04-26`, and are rendered distinctly (grey) — never counted as a current sanction.
- **Lunar Tide / Rosalind**: the UK correction notice (10 Feb 2026, UID **RUS2841**) struck an erroneous
  flag value ("Tazmania") *without replacement*. The flag recorded in the dataset is **Guinea**, taken
  from the OFAC ROSALIND entry; `flagSourceUrl` points to OFAC (Recent Actions 20251231), **not** the UK
  notice. UK gives `ownerOperator` (West Maritime); OFAC/sb0348 gives `registeredOwner` + `interestHolder`
  (Winky) — recorded as separate dated assertions, flagged as an unreconciled source discrepancy.
- **Arctic LNG 2 LLC**: designation is tied to its **inclusion on 2 Nov 2023** (OFAC 20231102), with
  Tax ID `8904075357`, registration `1148904001278` and the Novy Urengoi address. The 5 Sep 2024
  action is used only for the Gotik / Plio → Arctic LNG 2 `linkedTo` links.
- **Venezuela**: four tankers delisted by OFAC in 2020 were removed entirely. The scope is **not limited
  to Russia**: Lunar Tide / Rosalind (IMO 9277735) is also OFAC-listed under `VENEZUELA-EO13850`.

## Screening view = discrete signals (no score)

There is deliberately **no composite risk score and no high/elevated tiers** — a weighted sum with
unpublished weights reads as a wrongdoing verdict. The screening view shows discrete, individually
sourced signals grouped by kind: **status** (sanction facts; only a status-verified listing counts as
a current sanction), **observations** (neutral — open-registry flag per the ITF FoC list; flag vs
listed-address; cluster counts explicitly *within this dataset*), and **completeness** (data gaps,
informational only). Missing data never implies wrongdoing.

## Data hygiene & status rendering

- A **single shared view-model** (`designationPresentation`, `src/lib/status.ts`) maps `currentStatus`
  to colour + label + source links for **all five views including the map**: **active** (red, verified),
  **removed** (grey, with delisting date), and **current-unverified** (amber, "listed; current status
  unverified") — the amber state is supported by the renderer though no record currently uses it. The map
  colours each arc by this lifecycle status and shows it in the tooltip — so a removed vessel renders grey,
  never red.
- `jurisdictionOfIncorporation` is separated from `describedAsBasedIn` and the listed-address country.
  It is filled only from **official registration identifiers present in the cited OFAC action** —
  Russian Tax ID + registration number for Sovcomflot (7702060116 / 1027739028712) and Arctic LNG 2
  (8904075357 / 1148904001278). This is not a corporate-registry pull; it is null everywhere else.
- Port **UN/LOCODE** is proved by the **UNECE LOCODE service** (`codeSourceUrl`); the UNECE rows for
  `RU PRI` / `CN ZOS` carry no coordinates, so **coordinates have a separate `coordinateSourceUrl`** and
  are flagged `coordinateStatus = approximate` (port/geographic source). Brookings sources only the
  voyage.
- Designation edges and the Trace table expose **two links** — the *listing* action and the
  *delisting / current-status* source — plus status, verified date and removal date.
- The denormalised `Vessel.status` field was removed — vessel status is derived from its designations.
- The merged `data/dataset.json` is a **generated** convenience artifact (regenerate with `npm run
  data:normalize`); it is **gitignored, not committed**, so it cannot drift from `data/seed/*.json`
  (which the explorer actually reads). CI regenerates `data/seed` + `data/geo-csv` and fails on drift.

## The explorer (five views)

Overview (vessel table), Map (flag vs listed-address geography + the one reported voyage), Network
(vessel → related company → authority; click an edge for provenance), Trace (one vessel end-to-end),
Screening (discrete signals). Map uses deck.gl; the graphs use Cytoscape. Heavy libraries load
client-side only.

## Build & reproducibility

- Stack: **Next 15.5.19 + React 19**, deck.gl 9.1+, Cytoscape 3.30. `npm audit --omit=dev` → **0
  vulnerabilities**.
- `npm audit` (full, incl. dev): **0 vulnerabilities** (`fast-xml-parser` upgraded to 5.x).
- The production build **compiles cleanly in this sandbox** (all six routes prerender as static); a
  full clean build log is committed at `docs/build-log.txt`. `.nvmrc` pins the **exact** version
  `22.22.2` and the committed build log is from that same runtime. To mitigate the slow/stalled
  "Collecting build traces" step on constrained machines, `next.config.js` excludes the large
  client-only trees (three / deck.gl / luma.gl / cytoscape) from server output-file tracing. CI
  (`.github/workflows/build.yml`) has a **20-minute timeout** and runs `npm ci` → typecheck →
  seed/QA/CSV → `data:normalize` → a **drift check** (`git diff --exit-code data/seed data/geo-csv`)
  → `npm run build` → `npm audit` as **hard gates** (no `|| true`). The one thing not executable from
  this sandbox is an actual public **GitHub Actions run** under the pin — that remains a reviewer
  step; everything else here is run and logged.

## Run

```bash
nvm use                         # Node 22.22.2 (see .nvmrc)
npm ci
npm run data:seed               # regenerate data/seed/*.json
npm run data:qa                 # structural validation + IMO check digit
npm run geo:csv                 # emit data/geo-csv/*.csv (candidate export)
npm run typecheck:lib           # strict typecheck of src
npm run build                   # production build (telemetry off)
npm run dev                     # explorer at http://localhost:3000
```
